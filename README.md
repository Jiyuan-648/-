## 1. 任务拆解与 AI 协作策略

本次作业包含6项分析任务，涉及数据预处理、时间分析、统计建模和可视化。我采用的协作策略是**分步拆解、逐任务验证**：

1. **先让 AI 读取并理解数据**：将 ICData.csv 前几行和数据字典一并提供给 AI，确保 AI 对字段含义有准确理解后再动手编码。
2. **逐任务推进**：每完成一个任务就运行验证，确认 print 输出和图表结果正确后再进入下一个任务。这样做的好处是：一旦发现问题可以立即定位到具体任务，避免后期大范围返工。
3. **关键约束前置声明**：在任务2开始时明确告诉 AI"从本任务起所有统计仅使用刷卡类型=0 的上车记录"，并在后续每个任务的 prompt 中重申该约束，防止 AI 遗忘。
4. **函数签名和图表要求先确认再编码**：对于任务3的函数签名和任务2/3/6的图表规范，均在 prompt 中以引用原文的方式给出，确保 AI 生成的代码100%匹配题目要求。
5. **人工审查 + 修正循环**：AI 生成代码后，我检查运行结果、图表格式和输出数值，发现问题时给出具体错误描述让 AI 修正，而不是自己手动改代码。

这种策略的核心思路是：**让 AI 做执行层的工作（编码），人做决策层的工作（需求理解、结果审核、格式把关）**。

## 3. Debug 记录

### 报错现象
任务5导出的 txt 文件中，车辆编号和驾驶员编号显示为浮点数格式（如 `9132.0` 而非 `9132`），不符合预期。

### 解决过程
1. **定位原因**：检查原始 CSV 数据发现「驾驶员编号」列在 pandas 读取时被自动推断为 `float64` 类型（因为部分值为 NaN 或隐含小数），导致写文件时输出带 `.0` 后缀。
2. **尝试方案A**：在 `read_csv` 时指定 `dtype={'驾驶员编号': int}`。但该方案失败，因为该列确实存在缺失值（虽然任务1中已删除，但读取时先于预处理）。
3. **最终方案**：在写入 txt 文件时，使用 `int(row['车辆编号'])` 和 `int(row['驾驶员编号'])` 显式转换为整数后再写入。这样既不影响上游数据处理，又保证了输出格式的正确性。
4. **验证**：重新运行后检查 1101.txt，确认输出格式为纯整数的 `车辆编号 驾驶员编号` 对应关系。

## 4. 人工代码审查（逐行中文注释）

以下是任务4 PHF 计算的核心代码及逐行中文注释：

```python
# --- 高峰小时自动识别 ---
# 对上车数据按小时分组，统计每个小时的刷卡量
hourly_counts = boarding.groupby("hour").size()
# idxmax()返回刷卡量最大的小时的索引值，即高峰小时（0-23的整数）
peak_hour = hourly_counts.idxmax()
# max()返回高峰小时对应的刷卡量数值
peak_hour_count = hourly_counts.max()

# 输出高峰小时信息，格式为 HH:00 ~ HH+1:00
print(f"高峰小时：{peak_hour:02d}:00 ~ {peak_hour + 1:02d}:00，刷卡量：{peak_hour_count} 次")

# 筛选高峰小时内的所有刷卡记录
peak_hour_data = boarding[boarding["hour"] == peak_hour].copy()
# 提取每条记录的交易分钟数（0-59），用于后续5/15分钟窗口划分
peak_hour_data["minute"] = peak_hour_data["交易时间"].dt.minute

# --- 5分钟粒度统计与PHF5计算 ---
# 用地板除法将分钟值映射到5分钟窗口的起始值：0→0, 4→0, 5→5, ..., 59→55
peak_hour_data["min5_bin"] = (peak_hour_data["minute"] // 5) * 5
# 按5分钟窗口分组，统计每个窗口的刷卡量
min5_counts = peak_hour_data.groupby("min5_bin").size()
# 找出12个窗口中刷卡量最大的值及其起始分钟数
max_5min_count = min5_counts.max()
max_5min_start = min5_counts.idxmax()
max_5min_end = max_5min_start + 5  # 窗口结束分钟 = 起始分钟 + 5

# PHF5 = 高峰小时总刷卡量 / (12 × 高峰小时内最大5分钟刷卡量)
# 其中12是因为一小时有12个5分钟窗口
phf5 = peak_hour_count / (12 * max_5min_count)

# --- 15分钟粒度统计与PHF15计算 ---
# 将分钟映射到15分钟窗口：0-14→0, 15-29→15, 30-44→30, 45-59→45
peak_hour_data["min15_bin"] = (peak_hour_data["minute"] // 15) * 15
# 按15分钟窗口分组，统计每个窗口的刷卡量
min15_counts = peak_hour_data.groupby("min15_bin").size()
# 找出4个窗口中刷卡量最大的值及其起始分钟数
max_15min_count = min15_counts.max()
max_15min_start = min15_counts.idxmax()
max_15min_end = max_15min_start + 15  # 窗口结束分钟 = 起始分钟 + 15

# PHF15 = 高峰小时总刷卡量 / (4 × 高峰小时内最大15分钟刷卡量)
# 其中4是因为一小时有4个15分钟窗口
phf15 = peak_hour_count / (4 * max_15min_count)
```

**关键理解点：**
- `// 5 * 5` 是整数地板除法的经典技巧，将连续值映射到离散区间起点（如 7→0*5=0, 12→2*5=10）
- PHF 分母中的 12 和 4 分别来自 60÷5 和 60÷15，代表一小时内的时间窗口个数
- PHF 值域为 0~1，值越接近1说明高峰小时内客流分布越均匀；值越小说明存在明显的短时尖峰
